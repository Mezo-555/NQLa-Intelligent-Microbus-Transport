# NQLa Admin Dashboard — مهام التنفيذ

> النطاق الحالي: لوحة ويب Admin مستقلة عن تطبيقي Flutter، ببيانات وتدفقات Mock مترابطة، مع طبقة بيانات مركزية قابلة للاستبدال بـBackend API. الخادم وقاعدة البيانات ونماذج AI الحقيقية مؤجلة إلى حين جاهزية فريق Backend/AI.

## Dashboard ومؤشرات التشغيل
- [x] Dashboard تعرض مؤشرات تشغيلية مختصرة، ملخصات الطلبات والرحلات، وحالات السائقين والركاب ببيانات تجريبية مترابطة. الأرقام الأساسية مشتقة من سجلات العينة نفسها، ومخطط الأسبوع الاصطناعي معرّف بوضوح كبيانات توضيحية.

## إدارة السائقين
- [x] إدارة السائقين عبر قائمة قابلة للبحث والتصفية، عرض التفاصيل والحالة، وتنفيذ إجراءات إدارية تجريبية.

## إدارة الركاب
- [x] إدارة الركاب عبر قائمة قابلة للبحث والتصفية، ملفات تفصيلية، وسجل نشاط تجريبي لكل راكب.

## إدارة الطلبات
- [x] إدارة الطلبات مع استعراض حالاتها وتفاصيل نقاط الانطلاق والوصول والأطراف المرتبطة، إضافة إلى تحديثات حالة تجريبية. الإسناد يربط الطلب بسائق متاح وينشئ رحلة تجريبية مرتبطة.

## إدارة الرحلات
- [x] إدارة الرحلات مع تفاصيل الرحلة والسائق والراكب والمسار والتوقيت والتكلفة والحالة ضمن تدفق تجريبي قابل للتجربة. إكمال/إلغاء رحلة مرتبطة يحدّث الطلب وحالة السائق بما يحافظ على ترابط بيانات العينة.

## الخريطة التشغيلية
- [x] صفحة خريطة تشغيلية لعرض السائقين والرحلات والطلبات والمحطات مكانيًا باستخدام مواقع وبيانات تجريبية، مع طبقات قابلة للتبديل ورسالة خطأ وإعادة محاولة.

## إدارة المسارات والمحطات
- [x] إدارة المسارات والمحطات من خلال قوائم وعروض تفصيلية وعلاقات واضحة بين كل مسار ومحطاته. يمكن إضافة مسار ومحطة أو حذف محطة تجريبية، مع الحفاظ على محطتي البداية والنهاية.

## التقارير
- [x] صفحة تقارير تتضمن جداول وملخصات ورسومًا لمؤشرات الأداء والتشغيل اعتمادًا على البيانات التجريبية، مع تصدير CSV. إجماليات الجداول مشتقة من سجلات الرحلات؛ الاتجاه الأسبوعي التوضيحي موسوم بأنه اصطناعي.

## التنقل والحالات والاستجابة
- [x] تنقل إداري واضح بين صفحات ووحدات مستقلة، مع حالات تحميل وفراغ وأخطاء تجريبية وتجربة متجاوبة للشاشات المختلفة. يمكن تجهيز خطأ تحميل تجريبي من قائمة وضع العرض ثم مشاهدته عند فتح صفحة أخرى وإعادة المحاولة.

## طبقة البيانات التجريبية
- [x] طبقة خدمات وبيانات Mock مركزية بعقود نماذج موحدة، بما يسمح باستبدالها لاحقًا بمصدر API دون إعادة بناء الواجهات. بيانات الجلسة مؤقتة ولا تُحفظ بعد إعادة التحميل.

## تحسين بصري وواجهة التشغيل
- [x] رفع مستوى مركز التشغيل بواجهة عربية RTL أكثر تميزًا ووضوحًا، بهرمية بصرية محسّنة وبطاقات تشغيل ورسوم وطرق وصول سريعة، مع الحفاظ على ألوان NQLa وسلوك بيانات Mock الحالي والتجاوب مع الهاتف.

## دليل ربط API وقاعدة البيانات
- [x] إضافة شرح عربي تعليمي يوضح أن React يطلب البيانات عبر Backend API ولا يتصل بقاعدة البيانات مباشرة، مع خطوات تجهيز عناوين API، عقود الطلب/الاستجابة، استبدال طبقة Mock الحالية تدريجيًا، المصادقة ومعالجة الأخطاء، وأمثلة متوافقة مع ملفات المشروع.

## واجهات AI/ML التجريبية المكتملة في Admin

> البنود التالية مكتملة كواجهة عربية وتدفقات Mock فقط. لا تعني أن موديل ML/NLP/LLM أو قاعدة البيانات أو GPS الحقيقي متصل؛ التكاملات الفعلية مدرجة في القسم التالي.

- [x] **مؤشرات حداثة البيانات وعدم اليقين:** تعرض صفحة AI حالة اتصال النموذج ونسخته وتقييمه ومصدر/حداثة العينة. تعرض شاشة Forecast حدود التوقع وعمر بيانات العرض وحالة القدم، وتعرض NLP ثقة غير معايرة وملاحظة عدم اليقين ووقت العينة، وتعرض السلامة لقطة مؤرخة وعدم اليقين، ويعرض المساعد المصدر والحداثة وعدم اليقين والامتناع. جميع القيم موسومة Demo ولا تدّعي تحديثًا حيًا.
- [x] **عرض التنبؤ والعرض/الطلب — FR-9.1، FR-10.1–10.2، AIQ-03:** تبويب الطلب يعرض مناطق وفترات توضيحية، الطلب المتوقع، المقاعد الحرة، نطاقًا توضيحيًا، العجز/الفائض بالمقاعد، نسخة النموذج، عمر عينة العرض والتنبيه عن البيانات القديمة. يوضح أن التقييم بـMAE/RMSE وخط أساس held-out غير متوفر؛ لا توجد نتيجة inference أو حفظ دائم.
- [x] **عرض إعادة التوزيع والحوافز — FR-11.1–11.3، AIQ-04:** بطاقات التوصية تعرض السائق/المسار والمنطقة/النافذة والفجوة قبل/بعد والحافز والشروط، وتجرّب حالات إرسال/قبول/رفض داخل Mock فقط. لا ترسل عرضًا حقيقيًا ولا تحرك سائقًا.
- [x] **واجهة مراجعة NLP بالعربية المصرية وFranco-Arabic — FR-12.1–12.2، AIQ-02، UR-A05:** عينات تجريبية تعرض المشاعر وفئة الشكوى/السلامة والثقة غير المعايرة وملاحظة عدم اليقين ووقت العينة؛ تعرض أنماط الفئات والمشاعر مجمعة، مع تأكيد/تصحيح/تصعيد بشري تجريبي. لا يوجد موديل ولا مقاييس Precision/Recall/Macro-F1 فعلية.
- [x] **واجهة مراجعة السلامة البشرية — FR-12.3–12.5، AIQ-05:** تعرض لقطة Demo ودرجة غير معتمدة وعوامل/مصدر/عدم يقين، وتسمح بتجريب مراجعة/طلب تصحيح، مع التنبيه إلى عدم وجود عقوبة تلقائية. واجهة السائق في تطبيق Track 1 منفصلة.
- [x] **واجهة مساعد Transportation AI — FR-14.1–14.5، UR-G04، AIQ-06:** محاكاة أسئلة المشرف وتلخيص بيانات Mock مع مصادر وحداثة وعدم يقين وامتناع عند نقص الدليل أو سؤال حساس، وتضيف أثرًا تجريبيًا في Audit. لا يوجد LLM/RAG أو اتصال Backend.
- [x] **لوحة التنبيهات والحوكمة والتقارير — UR-A02–A05، FR-13.1–13.3، NFR-11–12، NFR-14:** قوائم تنبيهات بعمر/مصدر Demo، إعدادات عتبات وسياسة مؤقتة في الذاكرة، سجل تدقيق وتصدير CSV للتجربة. التعرفة والمدفوعات والغرامات والبيانات الإنتاجية غير موصولة.
- [x] **خلفية الخريطة الجغرافية — Track 1 / BR-07–08:** MapLibre يعرض خلفية OpenFreeMap المستندة إلى OpenStreetMap وطبقات السائقين والطلبات والرحلات والمسارات والمحطات مع إسناد المصدر؛ إحداثيات السائقين Mock وليست GPS ولا تمثل نسبة حداثة حقيقية.
- [x] **عقد التكامل والتتبّع — فصول 3–4:** الدليل العربي يربط صفحات Admin بمتطلبات FR/UR/AIQ، ويقترح مسارات API وصلاحيات وأشكال JSON للـForecast وNLP ومراجعات السلامة والمساعد، وغلاف أخطاء وحقول freshness/model-version/audit. المسارات أمثلة للنقاش وليست إلزامًا للفريق.
- [x] **الحفاظ على تجربة قاعدة التدريب:** يحتفظ المشروع بعميل القراءة التجريبي لقائمة السائقين عبر `adminHttpApi.ts` و`VITE_API_BASE_URL`؛ لا يضم `.env.local` أو كلمات مرور. بقية وحدات AI تبقى محاكاة محلية.

## متطلبات التشغيل الحقيقي التي تنتظر فريق Backend/AI/Mobile

- [ ] **التنبؤ بالطلب وفجوة العرض — FR-9.1، FR-10.1–10.2، AIQ-03:** تعرض وحدة الإدارة توقعات الطلب حسب المنطقة والنافذة الزمنية اعتمادًا على سجل الرحلات وجغرافيا المسارات/المحطات والخصائص الزمنية؛ تعرض نسخة الموديل وحالة التقييم وحداثة البيانات وعدم اليقين. تقدّر العرض بمقاعد مجانية وبمواقع السائقين المسموح بها، وتستبعد المواقع القديمة أو غير المتاحة؛ تحسب العجز/الفائض بمقياس المقاعد، تحفظ نتائج الفجوة وتصدر تنبيهًا عند تجاوز العتبة. لا يعرض النموذج دقة ML على أنها مقاسة ما لم تتوفر نتيجة تقييم على فترات held-out ومقارنة بخط أساس المتوسط التاريخي.
- [ ] **إعادة التوزيع والحوافز — FR-11.1–11.3، AIQ-04:** تعرض توصيات اختيار سائقين متوافقين مع المسار وقريبين من العجز، وتقدّر المقاعد الحرة الناتجة قبل التوصية لتقليل الفائض وتظهر الفجوة المتبقية عندما تكون السعة غير قابلة للتجزئة. التوصيات طوعية وتوضح المنطقة/الفترة/قيمة الحافز وشروط الاستحقاق؛ حالات الإرسال والقبول والرفض تسجل للعرض والتقارير. واجهة Mock لا ترسل عرضًا حقيقيًا للسائق ولا تنفذ إعادة توزيع فعلية.
- [ ] **تحليل ملاحظات الركاب والشكاوى بـNLP — FR-12.1–12.2، AIQ-02، UR-A05:** تدعم الخدمة الفعلية نصوصًا حرة باللهجة المصرية بالعربية أو Franco-Arabic؛ تعرض فئة المشاعر وفئة الشكوى/السلامة ومؤشر عدم اليقين ونسخة الموديل وحالة المراجعة البشرية. تشمل التقارير إحصاءات أنماط الشكاوى المجمعة ومراجعة الأحداث المصرح بها. لا تعرض مقاييس Precision/Recall/Macro-F1 كأداء فعلي دون تقييم held-out منفصل لكل مهمة وخط/لهجة.
- [ ] **مؤشرات سلامة السائق ومراجعتها — FR-12.3–12.5، AIQ-05:** تعرض الخدمة الفعلية لقطة سلامة مؤرخة وقابلة للتفسير من إشارات مُتحقق منها وتقييمات ومؤشرات حركة مسموح بها أثناء الوردية/الرحلة فقط، وتوضح الأدلة والمساهمة وعدم اليقين. يتيح النظام للسائق رؤية بياناته وتقديم اعتراض/تصحيح مع مراجعة بشرية وقرار ومراجع وسجل تدقيق. لا يفرض النظام عقوبة أو إجراءً سلبيًا تلقائيًا اعتمادًا على الدرجة وحدها، ولا يستنتج عقوبة من حدث منفرد.
- [ ] **مساعد Transportation AI الفعلي للمشرف — FR-14.1–14.5، UR-G04، AIQ-06:** يوفر واجهة أسئلة طبيعية وتلخيص تقارير؛ الإجابة تستند فقط إلى بيانات وخدمات NQLa المعتمدة التي يسمح بها دور المستخدم، وتعرض المصدر/حداثة البيانات وعدم اليقين، وتمتنع عند نقص الدليل أو تجاوز الصلاحية. تسجل الاستعلامات واستخدام الأدوات في سجل تدقيق محمي. لا ينفذ دفعًا أو عقوبة أو حكم سلامة أو إجراء تشغيل نهائي دون تأكيد بشري مخول.
- [ ] **تنبيهات وتقارير وسياسات حقيقية — UR-A02–A05، FR-13.1–13.3، NFR-11–12، NFR-14:** تقرأ تقارير مخولة من Backend على الرحلات والطلب والحوافز والأجور والمدفوعات والعقوبات وتحليلات السلامة، وتنتج تنبيهات ذات أولوية للعجز والبيانات القديمة وحالات السلامة. تخزن عتبات وسياسات ذات تاريخ نفاذ وسجل تغييرات بعد اعتمادها؛ لا تُعامل إعدادات Mock كسياسة تشغيل.
- [ ] **خريطة التشغيل وحداثة GPS — Track 1 / BR-07–08:** توصل مواقع الهاتف المصرح بها إلى Backend أثناء التوفر/الرحلة النشطة، وتعرض وقت القياس/عمر الإحداثي وحالة الحداثة حسب سياسة الفريق مع طبقات السائقين/الطلبات/الرحلات والمسارات والمحطات. لا تستخدم إحداثيات Demo على أنها GPS ولا تحسب نسبة freshness بلا بيانات زمنية حقيقية.
