# خطة إكمال لوحة NQLa Admin

## النطاق

استكمال الحزمة الحالية للوحة ويب Admin المستقلة لمشروع NQLa؛ لا إعادة بناء ولا نقل إلى Flutter. المحافظة على وحدات Dashboard والسائقين والركاب والطلبات والرحلات والخريطة والمسارات والتقارير وذكاء التشغيل. المطلوب الآن: إكمال عقد الربط والتتبّع إلى FR/UR/AIQ، إظهار حداثة البيانات وعدم اليقين بوضوح في تبويبات AI، والتحقق من البناء وإعداد ZIP مباشر الاستخراج إلى مجلد `apps`.

الخدمات الخلفية والنماذج الحقيقية والمصادقة والإنتاج خارج نطاق هذه المرحلة لأن Backend الفريق لم يبدأ؛ يظل مصدر البيانات Mock، مع الحفاظ على عميل HTTP التدريبي للقراءة فقط لقائمة السائقين. يمنع وسم قيم Demo كـGPS أو تنبؤ أو دقة موديل حقيقية.

## التصميم

- **الحركة التصميمية:** غرفة عمليات مدنية رقمية بطابع تحريري هادئ، مبنية على نظام NQLa الموجود بدل إدخال قالب جديد.
- **المبادئ:** وضوح مصدر البيانات؛ فصل الإشارة عن القرار؛ هرمية تشغيلية قابلة للمسح السريع؛ RTL ومتجاوبة.
- **الألوان:** كحلي/أزرق رمادي للثقة، تركواز NQLa للحركة والحالة النشطة، كهرماني للتحذير وعدم اليقين، وأسطح بيضاء ورمادية لعرض الجداول دون ضجيج.
- **التخطيط:** شريط جانبي ثابت على سطح المكتب، مساحة عمل مرنة، رأس صفحة مختصر، وبطاقات وطبقات متخصصة للخرائط والجداول؛ لا تحويل اللوحة إلى شبكة بطاقات متطابقة.
- **العناصر المميزة:** علامة NQLa التركوازية؛ شرائح مصدر/حداثة/حالة صغيرة؛ لوحات بيانات مع حدود تفسيرية وأسطر تدقيق.
- **التفاعل والحركة:** إجراءات Mock معنونة، تأكيدات وحالات تحميل/خطأ ظاهرة؛ انتقالات قصيرة؛ احترام `prefers-reduced-motion`.
- **الخط:** المحافظة على `IBM Plex Sans Arabic` مع fallback عربي من النظام، وخط Arial للبيانات اللاتينية فقط كما في النظام الحالي.
- **جوهر العلامة وصوتها:** لوحة تشغيل واضحة، مسؤولة، وموثوقة؛ العبارات تصف الحالة لا المبالغة. أمثلة: «عينة محلية — لا يوجد تحديث حي» و«مراجعة بشرية قبل أي إجراء مؤثر».
- **الشعار واللون:** الاحتفاظ بعلامة NQLa وأصل `logoUrl` الحالي في إعداد المشروع؛ اللون المملوك للعلامة هو التركواز `#0D8587`.

## التنفيذ والبنية

تظل React 19 وTypeScript وVite وReact Router والبنية الحالية دون اعتماديات جديدة. الوحدات في `src/features/`، والنماذج وواجهات البيانات في `src/data/`، ومكونات التنسيق المشتركة في `src/components/` و`src/layout/`. تستخدم `mockAdminApi.ts` و`mockAiAdminApi.ts` للعرض؛ `adminHttpApi.ts` يبقى محول HTTP اختياريًا لقراءة السائقين فقط. تظل الخريطة على MapLibre GL/OpenFreeMap/OSM مع إسناد ظاهر ومواقع Mock.

تُستكمل `AI_ADMIN_API_CONTRACT_AR.md` بمصفوفة الصفحة→API→الكيانات والصلاحيات، أمثلة JSON للـforecast وNLP والسلامة والمساعد والحوافز، قواعد freshness/uncertainty، مصادر الخرائط، والتقييم المطلوب قبل إطلاق أي نموذج. يتحدث `README_AR.md` و`BACKEND_INTEGRATION_AR.md` ليطابقا حالة الملفات الفعلية.

في واجهة AI تظهر حالة اتصال النموذج وحداثة مصدر البيانات عالميًا، مع عدم يقين وحدود التوقع وعمر بيانات العرض في Forecast، ومؤشر عدم اليقين ووقت/مصدر العينة في NLP والسلامة، ومصدر/حداثة/عدم يقين في إجابات المساعد والتنبيهات. تبقى كل البيانات المصطنعة موسومة بوضوح.

## هيكل المشروع

- `src/features/dashboard|drivers|passengers|requests|trips|map|routes|reports|ai/`: صفحات الوحدات ومسؤولية العرض وسلوكها.
- `src/data/`: أنواع النماذج، Mock APIs وقواعد الانتقال، ومحولات HTTP.
- `src/components/` و`src/layout/`: العناصر المشتركة والتنقل وهوية Admin.
- `public/`: الأصول و`manus-routes.json` لمسارات SPA.
- ملفات الجذر `README_AR.md`, `BACKEND_INTEGRATION_AR.md`, `AI_ADMIN_API_CONTRACT_AR.md`, `TODO.md`, و`plan.md`: تشغيل المشروع ومتطلبات التكامل والتتبّع.

## التسليم

يُتحقق من `pnpm build` ومن تشغيل الخادم وHTTP 200 لكل مسار SPA ومن صحة `/manus-routes.json`. تُجهز ZIP بمحتويات المشروع في جذر الأرشيف، دون مجلد أب إضافي أو `node_modules` أو `dist` أو `.git` أو `.env.local`؛ تُضمّن ملفات المصدر والوثائق وملفات pnpm lock. يشرح التسليم الاستبدال في `apps/admin_dashboard_web/admin_dashboard_web/` مع الاحتفاظ يدويًا بملف `.env.local` المحلي ثم التثبيت والتشغيل.
