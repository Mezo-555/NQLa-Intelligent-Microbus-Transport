# NQLa Admin Dashboard

لوحة **ويب React + TypeScript + Vite** مستقلة عن تطبيقي Flutter للسائق والراكب. الواجهة عربية RTL. المصدر التجريبي الأساسي في `src/data/mockAdminApi.ts` و`src/data/mockAiAdminApi.ts`. يوجد تكامل قراءة اختياري لقائمة السائقين عبر API تدريبي، لكنه لا يغيّر أي سجل.

## التشغيل المحلي

افتح الطرفية داخل المجلد الذي يحتوي `package.json`، ثم:

```powershell
pnpm install
pnpm dev
```

افتح عنوان Vite الذي يظهر، غالبًا `http://localhost:3000`. لإيقافه اضغط `Ctrl+C`. لفحص نسخة الإنتاج محليًا:

```powershell
pnpm build
pnpm preview
```

## الصفحات

- **الرئيسية ومركز التشغيل:** مؤشرات تشغيلية، تدفق طلبات/رحلات، وروابط سريعة. معظم الأرقام مرتبطة بعينة Mock؛ لا تعني اتصالًا مباشرًا بالأسطول.
- **السائقون:** البحث والتصفية والملف. عند ضبط `VITE_API_BASE_URL` تقرأ القائمة من `GET /admin/drivers`؛ من دون العنوان تستخدم العينة المحلية. API التدريب الحالي للقراءة فقط، لذا إجراءات تغيير الحساب معطلة في وضع API.
- **الركاب والطلبات والرحلات والمسارات والمحطات:** تدفقات Admin قابلة للتجربة محليًا ببيانات مترابطة. إسناد طلب Mock ينشئ رحلة Mock مرتبطة، وتحديث الرحلة يحدّث الطلب/توفّر السائق في العينة.
- **الخريطة التشغيلية:** خريطة جغرافية للإسكندرية باستخدام MapLibre وOpenFreeMap المبني على بيانات OpenStreetMap. طبقات السائقين والطلبات والرحلات والمسارات والمحطات تفاعلية؛ الإحداثيات المعروضة أمثلة اصطناعية وليست GPS حيًا.
- **التقارير:** ملخصات الرحلات والمسارات وCSV، إضافة إلى نطاق تقارير الطلب والحوافز وNLP والسلامة والتعرفة والمدفوعات والغرامات. كل قيمة موصولة/غير موصولة موسومة بوضوح؛ لا توجد دفعات أو غرامات أو مؤشرات دقة فعلية.
- **ذكاء التشغيل:** تبويبات للتنبؤ بفجوة المقاعد والحوافز، مراجعات NLP للعربية المصرية وFranco-Arabic، مراجعة سلامة بشرية، مساعد Admin، والتنبيهات والحوكمة. كلها محاكاة محلية؛ لا يوجد موديل ML/NLP/LLM متصل ولا قرار مالي أو عقوبة تلقائية.

## وصل قائمة السائقين بـAPI التدريب

إذا كان Backend التدريبي يعمل على `http://localhost:5000` وendpoint هو `GET /api/admin/drivers`، أنشئ `.env.local` بجوار `package.json`:

```env
VITE_API_BASE_URL=http://localhost:5000/api
```

أعد تشغيل `pnpm dev` بعد تغيير الملف. يجب أن يعيد endpoint مصفوفة JSON أو `{ "data": [...] }`. CORS على الخادم يسمح بأصل لوحة التطوير `http://localhost:3000`. لا تضع كلمة مرور قاعدة البيانات أو أي سر في متغير يبدأ بـ`VITE_`.

## بنية المشروع

- `src/features/`: صفحة/وحدة مستقلة لكل شاشة Admin.
- `src/layout/AdminLayout.tsx`: التنقل RTL وشريط اللوحة ووضع العرض التجريبي.
- `src/components/`: الجداول والبطاقات والحالات والنوافذ المشتركة.
- `src/data/types.ts` و`src/data/aiTypes.ts`: عقود النماذج بين الواجهة وطبقة البيانات.
- `src/data/mockAdminApi.ts` و`src/data/mockAiAdminApi.ts`: بيانات العرض وقواعد الانتقال المحلية.
- `src/data/adminHttpApi.ts`: محول API اختياري لقائمة السائقين؛ لا يتصل بقاعدة البيانات مباشرة.
- `src/hooks/useMockResource.ts`: حالات التحميل والخطأ وإعادة المحاولة.
- `public/manus-routes.json`: بيان مسارات صفحات الويب.

## الربط عندما يجهز Backend/AI

React لا يتصل بـPostgreSQL. المسار هو `React → HTTP/JSON → Backend → PostgreSQL`. ابدأ بتأكيد عقد كل endpoint وأنواع الحالات والصلاحيات مع زميل Backend، ثم استبدل خدمة Mock المقابلة بعميل HTTP مع الحفاظ على واجهة الصفحة. اقرأ [شرح الربط بالـBackend وقاعدة البيانات](BACKEND_INTEGRATION_AR.md)، و[عقد الوحدات الذكية المقترح وخريطة ارتباط الصفحات بالـAPI/DB](AI_ADMIN_API_CONTRACT_AR.md).

## حدود العرض التجريبي

التغييرات غير دائمة وتُصفّر عند إعادة التحميل. بيانات السائقين من API التدريب اختيارية وللقراءة فقط؛ باقي الأقسام، وطبقات AI، ومواقع الخريطة تجريبية. تسجيل الدخول والصلاحيات الحقيقية، التتبع الحي، التخزين الدائم، النماذج، المدفوعات والتنبيهات التشغيلية ليست موصولة. لا تستخدم هذا المشروع لإدارة بيانات إنتاجية.
